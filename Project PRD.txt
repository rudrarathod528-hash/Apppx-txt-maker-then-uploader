================================================================
        PRD — APPX COURSE BOT  (IMPROVED v2.1)
  Telegram-First Authorized Course Management & Media Bot
================================================================

PRODUCT TYPE
------------
Telegram-based Authorized Course Management & Media Processing Bot.

PRIMARY OBJECTIVE
-----------------
User apne authorized course account ko Telegram ke through login kare,
available courses dekhe, course ka complete content list (TXT) generate
karake Telegram par receive kare, aur authorized/officially accessible
media ko optionally process karke Telegram par receive kar sake.

CORE PRINCIPLE
--------------
"Telegram is the complete user interface."

User ko website/admin panel par jaane ki zarurat nahi honi chahiye.

Flow:

    Telegram
       ↓
    Login (Institute + ID + Password)
       ↓
    Secure Session
       ↓
    Courses
       ↓
    Course Content
       ↓
    TXT Export / Media Job
       ↓
    Telegram Delivery

2. CREDENTIAL HANDLING  (SAFE BY DESIGN)
================================================================

Credentials sirf authentication ke liye use honge.

FLOW:
    Username/ID
       ↓
    Password
       ↓
    Platform Login API
       ↓
    Authentication
       ↓
    Session / Access Token
       ↓
    Password immediately discard (memory + network buffer se)

RULES:
- Password kabhi STORE nahi hota.
- Password kabhi LOG nahi hota.
- Password TXT export me kabhi nahi jata.
- Password job data me kabhi nahi jata.
- Password Telegram logs me kabhi nahi jata.
- Database me password ka column hi NAHI HOTA.

JOBS/TXT me sirf authorized content metadata/references jati hai.


================================================================
3. SESSION MANAGEMENT
================================================================

Successful login ke baad backend authorized session maintain karta hai.

Stored data (encrypted reference):
    telegram_user_id
    platform_user_id
    tenant_id
    encrypted_session_reference
    token_expiry
    created_at
    updated_at

Raw password: NEVER STORED.

SESSION FLOW:
    Valid Session   → continue normally
    Expired Session → bot: "⚠️ Session expired. Please login again. [🔐 Login]"

SESSION TOKEN DELIVERY (user ka apna token):
    Login response se token automatically extract hota hai (JSON paths /
    Authorization header / cookie fallback — PLATFORM_TOKEN_JSON_PATH).
    User ko apna session JWT/access token (aur agar mile to refresh token
    + cookies) Telegram DM me milta hai:
      - login ke turant baad (SHOW_SESSION_TOKEN=yes, default)
      - /token command se kabhi bhi
      - Account menu me [🔑 Session Token] button se
    Security:
      - Token sirf usi user ke DM me jata hai (ownership check)
      - DB me encrypted reference; TXT me kabhi nahi; logs me kabhi nahi
      - Password kabhi token-message me nahi
      - Message me warning: token sensitive hai, share na karein

10. TXT EXPORT — IMPORTANT FEATURE
================================================================

[📄 Export Complete TXT]
    → "⏳ Generating content list..."
    → Authorized Content API
    → Normalize metadata
    → Generate TXT
    → Temporary TXT file
    → Telegram document upload
    → Temporary TXT delete

Filename example: physics_course.txt

TXT CONTENT FORMAT:

    APPX COURSE
    ============

    Course: Physics

    Chapter 01
    ----------

    Video 01
    Title: Motion
    Type: video
    Authorized reference: <platform-provided-reference>

    Video 02
    Title: Force
    Type: video
    Authorized reference: <platform-provided-reference>

    PDF 01
    Title: Chapter Notes
    Type: pdf
    Authorized reference: <platform-provided-reference>

TXT MUST NOT contain:
    - Password
    - Raw authentication credentials
    - Private session secrets
    - Cookies
    - Internal security headers
    - Another user's data

REFERENCE MODE (configurable — TXT_REFERENCE_MODE):

    base (DEFAULT, PRD-safe):
        Authorized reference: https://host/path/file.mp4
        (query params — signed tokens/sig/expires — TXT me nahi jate)
        → link ek identifier/reference ki tarah kaam karti hai;
          media download ke liye bot ka job system use karo.

    full (working-links mode):
        Authorized reference: https://host/path/file.mp4?token=..&sig=..&expires=..
        (platform-provided complete reference, signed URL bhi included)
        → TXT me header note add hota hai: links sirf account-owner ke
          personal authorized use ke liye; expire ho sakti hain.
        → password/session token/cookies kabhi nahi — sirf media reference.

    User ko TXT milne ke baad bhi media ke liye [⚙️ Create Media Job]
    recommended hai — kyunki signed URLs expire hote hain aur download
    authorized session ke saath hota hai.

13. MEDIA PROCESSING  (ONLY AUTHORIZED MEDIA)
================================================================

Sirf authorized/officially accessible media process hota hai.

Flow:
    Selected Content
       ↓
    Check authenticated access
       ↓
    Resolve platform-provided media resource
       ↓
    Download/process using permitted method
       ↓
    Temporary file
       ↓
    Telegram upload
       ↓
    Delete temporary file

Supported:
    - Direct downloadable media (mp4, mkv, webm, ...)
    - Platform-provided downloadable resources
    - HLS/DASH (.m3u8 / HLS content-type) — jab access/processing
      officially permitted ho (ffmpeg `-c copy` remux; DRM-free streams)
    - PDF and other supported formats

HLS (.m3u8) HANDLING:
    Detect: URL .m3u8/.m3 se end ho YA response Content-Type HLS ho
    (extension ke bina bhi — e.g. /playlist?token=..).
    Process: ffmpeg -i "<url>" -c copy -bsf:a aac_adtstoasc out.mp4
      (re-encode NAHI — sirf remux; CPU-light)
    ffmpeg missing → clean error: "HLS processing requires ffmpeg."
    Docker image me ffmpeg pre-installed hai.
    Auth header (agar same-host signed stream ho) ffmpeg ko -headers se
    pass hota hai.

DRM DETECTION + HANDLING:
    Reference/URL me DRM indicators mile (widevine, playready, fairplay,
    clearkey, license server, .mpd, drm=...) →
        ❌ Media cannot be processed through the available authorized
           method.   (code: drm_protected)
    DRM bypass attempt KABHI NAHI hota.
    Item fail hota hai — job rukta nahi, baaki items continue:
        [🔄 Retry] [⏭️ Skip] [📊 Job Status]

================================================================
18. RETRY SYSTEM
================================================================

Retryable errors (automatic retry, DEFAULT 3 attempts):
    - Temporary network error
    - Timeout
    - Telegram upload timeout
    - Temporary server error (5xx)

    Attempt 1 → Fail → Wait → Attempt 2 → Fail → Wait → Attempt 3
        → Fail → Mark Failed (user Retry/Skip buttons)

Non-retryable errors (immediate fail):
    - Unauthorized (401)
    - Content unavailable (404)
    - Permission denied (403)
    - Unsupported media
    - File too large

================================================================
37. TELEGRAM FILE LIMIT HANDLING
================================================================

Upload se pehle file size check:
    - ≤ MAX_UPLOAD_MB → normal upload
    - > limit → item fail: "❌ File too large for Telegram delivery."
    - Local copy turant delete (unnecessary copy nahi rakhte)
    - Bada upload (2 GB tak) → local Bot API server / api id+hash
      path documented (PRD §37, README me)

HLS stream media job me:
    playlist (m3u8) download → size check → ffmpeg remux → mp4 size
    check → Telegram upload → playlist + mp4 delete.

    ⏳ Please slow down. Try again in a few minutes.

DRM / UNSUPPORTED:
    ❌ Media cannot be processed through the available authorized method.

41. PLATFORM ADAPTER CONTRACT (CLASSX)
================================================================

Bot 2400+ ClassX/AppX white-label institutes support karta hai
(appxapis.json registry).

LOGIN:
    POST {base}{login_path}
    body:   {"username": "...", "password": "..."}
            (body/headers shape config se override ho sakta hai)
    success → token extract (configurable JSON path)
    headers me token: Authorization: Bearer <token>

COURSES:
    GET {base}{courses_path}  (authorized)
    → normalize → [{course_id, title, ...}]

CONTENT / COURSE CLASSES DISCOVERY:
    GET {base}{content_path.format(course_id=...)}
    → normalize → chapters/classes → items (video/pdf/other) → references

    Course ke andar "classes" kaise find hote hain:
      - API response ke common keys automatically detect hote hain:
        chapters, modules, sections, units, topics, batches, classes
      - Har chapter/class ke andar items: items, content, videos, pdfs,
        resources, lectures, lessons, classes, sessions
      - Titles: title, name, course_name, subject, topic, label
      - IDs: id, course_id, content_id, uuid, slug, video_id
      - Media references: secure_url, video_url, url, m3u8, hls_url,
        stream_url, pdf_url, file_url, download_url, source_url, link
      - Agar aapke platform ka structure alag ho → PLATFORM_* paths aur
        PLATFORM_LOGIN_* keys .env se override karo (README dekhein).

MEDIA RESOLVE:
    Item me platform-provided fields: video_url / m3u8 / pdf_url /
    file_url / secure_url ... → stream download
    HLS: ffmpeg -i "<url>" -c copy "<out>.mp4" (DRM-free streams only)

NORMALIZATION:
    Response JSON ke common shapes (data.* / result.* / payload.* /
    root array) ko handle karta hai; missing fields → best-effort.

MOCK MODE (PLATFORM_MODE=mock):
    Bina real credentials ke pura flow test karne ke liye:
    demo account (demo / demo123) + sample courses + sample content
    + generated sample media (TXT/PDF/MP4 via ffmpeg ya placeholder).

    Isse bot ko deploy se pehle end-to-end verify kiya ja sakta hai.

43. NON-GOALS  (YE SYSTEM KABHI NAHI KAREGA)
================================================================

This system is explicitly designed to NEVER:
    - bypass DRM (DMCA §1201 / India Copyright Act §65A — TPM
      circumvention offense hai; account hona ya bug-bounty kaam
      karna isse legal nahi banata)
    - defeat access controls
    - steal cookies / tokens
    - harvest credentials
    - access another user's account
    - access courses unavailable to the authenticated account
    - bypass CAPTCHA or anti-bot protections
    - expose private session information

BUG BOUNTY / SECURITY TESTING NOTE:
    Authorized testing ke liye vulnerability report ka matlab hota hai —
    chhota PoC (1-2 items) + report. Mass content extraction / DRM
    circumvention kisi bhi bug-bounty scope me kabhi nahi hota.

Agar content authorized method se process nahi ho sakta → clean
error message + item fail. Koi workaround nahi.

44. SUCCESS CRITERIA (MVP)
================================================================

MVP successful tab maana jayega jab:

1.  User Telegram se login kar sake (institute + ID + password).
2.  Password database/logs me save na ho.
3.  Login ke baad courses automatically show hon.
4.  User course select kar sake.
5.  Course ka content Telegram par browse kar sake.
6.  User one-click TXT export kar sake.
7.  TXT Telegram document ke roop me mil jaye.
8.  TXT me credentials/session secrets na hon.
9.  Authorized media ke liye job create ho sake.
10. Job sequentially process ho (one item at a time).
11. Progress Telegram message me update ho (edited message).
12. Failed items retry ho saken (auto 3x + manual Retry/Skip).
13. User job cancel kar sake.
14. Temporary files automatically delete hon (TTL cleanup).
15. Logout ke baad session securely clear ho.
16. Ek telegram user dusre user ka data access na kar sake.
17. Bot bina crash 24x7 chale (graceful error handling).
18. TXT me signed URLs (working links) config se on/off ho saken
    (TXT_REFERENCE_MODE=full) bina password/session secrets ke.
19. m3u8/HLS links media job me ffmpeg se mp4 ban kar Telegram par
    milein (ya clean error agar ffmpeg missing ho).
20. DRM-protected content detect ho kar clean fail ho — job continue
    kare, Retry/Skip mile; bypass kabhi na ho.
